## 5. Raw-index panic from "Close on host"

- `src/app/ids.rs:19` — new `public_workspace_id_checked(ws_idx) -> Option<String>`, shaped like the existing `public_tab_id`, with a comment naming the hazard (context-menu snapshot + resync shrinking `state.workspaces`).

**Not fixed, stated plainly:** the in-bounds-but-shifted index still resolves to whatever workspace now occupies that slot, and would close *that* one on the remote machine. Fixing it properly means carrying the stable workspace id in `ContextMenuKind::Workspace`/`GitWorkspace`/`Tab` instead of `ws_idx`. That enum is consumed across the sidebar rendering, mouse hit-testing and the whole modal action table, so it is a contract change well beyond wave 1 — I left it for wave 2 rather than pretend the shifted case is handled. `public_workspace_id` (the panicking one) is still used by other callers that pass a freshly computed index; I did not convert them.

- **Gated create send point** — `src/remote/federation/client.rs:213` adds `CreateRequestSendError` + `send_workspace_create_request`, the one place `WorkspaceCreateRequest` reaches the wire; the label clamp moved into it. `src/app/api/workspaces.rs:741` routes through it instead of a bare `out_tx.send`.
